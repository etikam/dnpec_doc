L'API DNPEC Collecte utilise l'authentification par token JWT (JSON Web Token). Chaque requête doit transmettre ce token dans l'en-tête HTTP `Authorization` sous la forme `Bearer <token>`. Le serveur valide le token à chaque appel, résout votre identité et applique les règles de contrôle d'accès correspondant à votre rôle. Aucune session côté serveur n'est maintenue : le token est la seule preuve d'identité.

<Warning>
  Ne stockez jamais votre token dans le code source ou dans une URL. Utilisez des variables d'environnement ou un gestionnaire de secrets (ex. : HashiCorp Vault, AWS Secrets Manager, un fichier `.env` exclu du contrôle de version).
</Warning>

## Obtenir un token

Les tokens d'accès sont délivrés par l'interface web de la plateforme DNPEC Collecte. Pour obtenir votre token :

<Steps>
  <Step title="Connectez-vous à la plateforme">
    Ouvrez la plateforme DNPEC Collecte dans votre navigateur et authentifiez-vous avec vos identifiants (adresse e-mail et mot de passe) fournis lors de votre inscription.
  </Step>
  <Step title="Récupérez votre token de session">
    Une fois connecté, votre token d'accès actif est disponible dans les paramètres de votre compte ou peut être copié depuis la console développeur de votre navigateur (onglet **Application → Local Storage**). Ce token est valide tant que votre session est active.
  </Step>
  <Step title="Utilisez le token dans vos appels API">
    Passez ce token dans l'en-tête `Authorization` de chaque requête, tel que décrit dans la section suivante.
  </Step>
</Steps>

<Info>
  Les tokens d'accès ont une durée de vie limitée (typiquement **1 heure**). Lorsque votre token expire, reconnectez-vous à la plateforme pour en obtenir un nouveau. Consultez la section [Renouveler le token](#renouveler-le-token) pour gérer l'expiration automatiquement dans vos intégrations.
</Info>

## Utiliser le token

Une fois le token obtenu, passez-le dans l'en-tête `Authorization` de chaque requête à l'API DNPEC Collecte. Le préfixe `Bearer` (avec une majuscule et un espace) est obligatoire.

```bash
curl https://votre-domaine/api/v1/campaigns \
  -H 'Authorization: Bearer VOTRE_ACCESS_TOKEN'
```

Voici comment intégrer ce mécanisme dans les environnements les plus courants :

<Tabs>
  <Tab title="cURL">
    ```bash
    # Stockez le token dans une variable d'environnement
    export DNPEC_TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

    curl https://votre-domaine/api/v1/submissions \
      -H "Authorization: Bearer $DNPEC_TOKEN"
    ```
  </Tab>
  <Tab title="JavaScript (fetch)">
    ```javascript
    const response = await fetch('https://votre-domaine/api/v1/campaigns', {
      headers: {
        'Authorization': `Bearer ${process.env.DNPEC_ACCESS_TOKEN}`,
        'Content-Type': 'application/json',
      },
    });

    const data = await response.json();
    ```
  </Tab>
  <Tab title="Python (requests)">
    ```python
    import os
    import requests

    headers = {
        "Authorization": f"Bearer {os.environ['DNPEC_ACCESS_TOKEN']}",
        "Content-Type": "application/json",
    }

    response = requests.get(
        "https://votre-domaine/api/v1/campaigns",
        headers=headers,
    )
    data = response.json()
    ```
  </Tab>
</Tabs>

## Renouveler le token

Les tokens d'accès expirent après une durée limitée. Pour continuer à appeler l'API sans interrompre votre intégration, implémentez l'une des deux stratégies suivantes :

- **Reconnexion automatique** : lorsque vous recevez une réponse `401 Unauthorized`, redirigez l'utilisateur vers la page de connexion de la plateforme pour qu'il obtienne un nouveau token.
- **Intercepteur HTTP** : dans votre client API, interceptez les réponses `401` et déclenchez le renouvellement de session avant de relancer la requête échouée.

<Tip>
  Implémentez un intercepteur HTTP dans votre client pour détecter automatiquement les réponses `401` et déclencher le renouvellement de session avant de relancer la requête échouée. Cela évite toute interruption visible pour l'utilisateur final.
</Tip>

## Erreurs d'authentification

Le tableau suivant récapitule les codes HTTP liés à l'authentification et les actions à entreprendre pour les résoudre.

| Code HTTP | Signification                          | Action                                                     |
|-----------|----------------------------------------|------------------------------------------------------------|
| `401`     | Token absent ou invalide               | Vérifiez que l'en-tête `Authorization` est bien présent et correctement formaté (`Bearer <token>`) |
| `401`     | Token expiré                           | Reconnectez-vous à la plateforme pour obtenir un nouveau token |
| `403`     | Accès refusé par les permissions       | Vérifiez votre rôle auprès de l'administrateur DNPEC ; certaines actions sont réservées aux analystes ou super admins |

<Note>
  Les données retournées par l'API sont filtrées automatiquement selon votre rôle et vos permissions. Un compte entreprise ne verra que ses propres soumissions et les campagnes qui lui ont été affectées — jamais les données d'une autre organisation.
</Note>
